## Hard rules

1. Give each language or region version its **own URL**. Do not swap language with cookies or `Accept-Language` alone. **FACT:** Google recommends different URLs; Googlebot usually crawls from the USA and does not send `Accept-Language`. Source: managing-multi-regional-sites.
2. Pick **one** hreflang delivery method (HTML `link`, HTTP `Link` header, or sitemap). The three are equivalent. Do not maintain all three unless you can keep them identical. **FACT:** localized-versions.
3. Make every alternate URL **absolute** (`https://…`). Do not use protocol-relative or path-only hrefs. **FACT:** localized-versions.
4. Include a **self-referencing** hreflang entry on every version. **FACT:** each language version must list itself and all others. Source: localized-versions.
5. Keep clusters **reciprocal**. If X names Y, Y must name X or Google may ignore the annotations. **FACT:** localized-versions.
6. Use **ISO 639-1** language plus optional **ISO 3166-1 Alpha-2** region (`en`, `en-GB`, `de-CH`). Language first. Region alone is invalid. Do not use `UK`, `EU`, `UN`, or `es-419`. **FACT:** localized-versions.
7. Point each page’s `rel=canonical` at **itself** (or the same-language preferred URL), not at another language. **FACT:** if you use hreflang, specify a canonical in the same language, or the best substitute language. Source: consolidate-duplicate-urls.
8. Do not combine `rel=canonical` with `hreflang` on the **same** `link` element. **FACT:** canonical annotations with `hreflang` / `lang` / `media` / `type` are ignored for canonicalization. Source: consolidate-duplicate-urls.
9. Do not auto-redirect users to another locale based on IP or guessed language. **FACT:** those redirects can hide versions from users and crawlers. Source: managing-multi-regional-sites.
10. Do not cloak by IP, user-agent, or language header. Serving different HTML to Googlebot than to users to manipulate rankings is spam. **FACT:** spam-policies (Cloaking).
11. Do not put `noindex` URLs in an hreflang cluster. **FACT:** `noindex` means do not show the URL in search results (robots-meta-tag). **FACT:** hreflang exists so Search can point users at the right localized URL (localized-versions). **JUDGMENT:** a URL that must not appear in Search cannot be a useful Search alternate; drop it from the cluster or remove `noindex`. Official localized-versions “common mistakes” list does not name this pairing.
12. Translate **main content**, not only chrome. **FACT:** Google detects language from visible content, not `lang` or the URL. Localized versions are duplicates only if the main content stays untranslated. Sources: managing-multi-regional-sites, localized-versions.
13. Write `title` and meta description in the **same language and script** as the page body. **FACT:** title-link; mismatch can cause Google to pick other title text.
14. Set `html lang` (and `dir="rtl"` when the page base direction is RTL) for users and assistive tech. **FACT:** W3C. **FACT:** Google does **not** use `hreflang` or HTML `lang` to detect page language. Source: localized-versions.

## 1. URL architecture: ccTLD vs subdomain vs subdirectory

**FACT** (managing-multi-regional-sites). Google’s locale-specific URL options:

| Structure | Example | Pros (Google) | Cons (Google) |
| --- | --- | --- | --- |
| Country-specific domain (ccTLD) | `example.de` | Clear geotargeting; server location irrelevant; easy site separation | Expensive / limited availability; more infrastructure; strict ccTLD rules; **one country only** |
| Subdomain on a gTLD | `de.example.com` | Easy to set up; different server locations OK; easy separation | Users may not read geotargeting from the URL (`de` = language or country?) |
| Subdirectory on a gTLD | `example.com/de/` | Easy to set up; low maintenance (same host) | Users may not read geotargeting from the URL; single server location; harder site separation |
| URL parameters | `example.com?loc=de` | — | **Not recommended.** Hard to segment; users may not recognize targeting |

**FACT:** Google treats most gTLDs (`.com`, `.org`, `.eu`, `.asia`, and listed vanity ccTLDs such as `.io`, `.me`, `.tv`) as generic, not country-tied. See the gTLD list on managing-multi-regional-sites.

**FACT:** ccTLDs (`.de`, `.fr`, `.jp`, …) are a **strong** country signal. Some countries restrict who may register them. Some vanity ccTLDs are treated as gTLDs.

**FACT:** Google also uses hreflang, server IP (weak; CDNs dilute it), local addresses/phones, local language and currency, local inbound links, and Business Profile signals. Google **ignores** locational meta tags (`geo.position`, `distribution`) and geotargeting HTML attributes.

**JUDGMENT — pick a structure:**

- One country, one brand, legal/local trust matters → ccTLD if you can operate it.
- Many countries or languages, one product, one engineering team → **subdirectory** (`/en-gb/`, `/de/`) unless you already have separate hosts.
- Separate stacks, legal entities, or cookie/consent regimes → subdomain or ccTLD.
- Never use query parameters for locale.

**Do this**

1. Freeze one pattern for the whole site. Do not mix `/de/` (language) and `/de-de/` (region) without a written map.
2. Use UTF-8 in URLs. Localized path words and IDNs are allowed. Escape links correctly. **FACT:** managing-multi-regional-sites.
3. Put a visible language/region switcher on every locale. Do not rely on detection.
4. If two hosts show the same language (e.g. `example.de` and `example.com/de/`), pick one preferred URL, canonicalize to it, and still annotate hreflang. **FACT:** managing-multi-regional-sites (“Handling duplicate pages”).

## 2. hreflang

**FACT:** hreflang tells Google that URLs are localized variations of the same content so Search can show the best language/region version. Google may find alternates without annotations; annotate anyway.

**FACT:** Google does **not** use hreflang (or `lang`) to detect the language of a page. Algorithms read visible text.

### When to annotate

**FACT** (localized-versions). Annotate when:

- Only the template (nav, footer) is translated and the main body stays in one language (forums, UGC).
- Same language, small regional differences (US / GB / IE English).
- Fully translated sites.

**FACT:** Localized versions count as duplicates **only if the main content is untranslated**.

### Method A — HTML `link` in `<head>`

Use when you control HTML and do not want sitemap complexity.

```html
<link rel="alternate" hreflang="en-gb" href="https://en-gb.example.com/page.html" />
<link rel="alternate" hreflang="en-us" href="https://en-us.example.com/page.html" />
<link rel="alternate" hreflang="en" href="https://en.example.com/page.html" />
<link rel="alternate" hreflang="de" href="https://de.example.com/page.html" />
<link rel="alternate" hreflang="x-default" href="https://www.example.com/" />
```

**FACT:** Put tags in a well-formed `<head>`. Do not merge hreflang with `media` or other alternate representations on one `link`. The **same set** must appear on every version.

### Method B — HTTP `Link` header

Use for non-HTML (PDF) or when you cannot edit `<head>`.

```
Link: <https://example.com/file.pdf>; rel="alternate"; hreflang="en",
      <https://de-ch.example.com/file.pdf>; rel="alternate"; hreflang="de-ch",
      <https://de.example.com/file.pdf>; rel="alternate"; hreflang="de"
```

**FACT:** Return the **same** header on every version, including the requested URL.

### Method C — XML sitemap

Use for large catalogs. Declare `xmlns:xhtml="http://www.w3.org/1999/xhtml"`.

**FACT:** One `<url>` per version. Each `<url>` contains a `<loc>` plus an `<xhtml:link>` for **every** alternate **including itself**. Child `xhtml:link` entries do not count toward the sitemap URL limit. Host the sitemap in a directory that may list those URLs. Follow general sitemap rules.

### x-default

**FACT:** `x-default` matches users whose language/region is not listed. Designed for language selectors and auto-redirecting home pages. No language code. The page language is irrelevant.

```html
<link rel="alternate" hreflang="en-gb" href="https://example.com/en-gb" />
<link rel="alternate" hreflang="en-us" href="https://example.com/en-us" />
<link rel="alternate" hreflang="x-default" href="https://example.com/country-selector" />
```

**JUDGMENT:** Point `x-default` at a real chooser or a global English (or primary) page, not at a random country store.

### Self-referencing and reciprocal

**FACT:** Each version lists itself and all others. If two pages do not both point to each other, the tags are ignored (prevents third parties from claiming your URLs).

**FACT:** If a full bidirectional mesh is hard, you may omit some pairings. Google still processes pairs that point to each other. Always bidirectionally link new locales to the **originating / dominant** language.

**Do this:** generate the cluster from one data source (locale → URL). Fail the build if any member is missing, non-200, redirected, or `noindex`.

### Language-region codes

**FACT** (localized-versions):

- Format: `language` or `language-region` (dash). Example: `en-US`.
- Language: ISO 639-1. Region: ISO 3166-1 Alpha-2. Only those lists. `es-419` is **not** supported.
- Language-only is valid: `de` = German, any region.
- `en-GB` = English for users in the UK.
- Script: country often implies script (`zh-TW` → Traditional). You may set ISO 15924: `zh-Hant`, `zh-Hans`, `zh-Hans-US`.
- Belgium: `de-be`, `nl-be`, `fr-be`. **`be` alone is Belarusian**, not Belgium.

**FACT:** If you have `en-ie`, `en-ca`, `en-au`, also provide a catchall `en` for unspecified English users.

**FACT:** URL tokens (`en`, `de` in the host or path) are **not** used to infer audience. You must map audience with hreflang (or a ccTLD).

### Common errors

**FACT** (localized-versions “Troubleshooting”):

| Error | What happens | Fix |
| --- | --- | --- |
| Missing return tags | Annotations may be ignored or misread | Every named URL must name the others, including the source |
| Incorrect language codes | Invalid | Language required; region optional; region-only invalid |
| Incorrect / reserved region codes | Google ignores that part (`EU`, `UN`, `UK`) | Use `GB` not `UK` |

**Also enforce (derived from official purposes):**

| Error | Why | Fix |
| --- | --- | --- |
| Relative or protocol-relative hrefs | **FACT:** URLs must be fully qualified | Absolute `https://` |
| Missing self link | **FACT:** each version must list itself | Add self `hreflang` |
| Canonical to another language | Conflicts with same-language canonical rule | Self-canonical per locale |
| `noindex` + hreflang | Alternate cannot appear in Search | Index the URL or drop it from the cluster |
| hreflang to redirects / 404 / blocked URLs | **JUDGMENT:** Google cannot treat a dead URL as the Search alternate | 200 + indexable + crawlable targets only |
| Combining hreflang with `media` on one `link` | **FACT:** do not combine | Separate `link` elements |

Google names third-party debug tools on localized-versions and states they are **not** maintained or checked by Google. Do not treat those tools as official.

## 3. Canonical vs hreflang

They solve **different** problems. Use both. Do not substitute one for the other.

| | Canonical | hreflang |
| --- | --- | --- |
| Job | Pick the **preferred URL** among duplicates / near-duplicates for crawling, signals, and the URL shown when Google treats pages as the same | Tell Google which **language/region variant** to show a given searcher |
| Typical target | Same language, tracking params, HTTP/HTTPS, www/non-www, print URLs | Cross-language or cross-region equivalents |
| Self reference | Yes, on the canonical page | Yes, every locale lists itself |
| Cross-language | Do **not** canonicalize `fr` → `en` | Do annotate `fr` ↔ `en` |

**FACT:** For similar or duplicate **same-language** multi-regional URLs (e.g. `example.de/` and `example.com/de/`), pick a preferred version and use **both** `rel=canonical` and hreflang so the correct language/regional URL is served to searchers. Source: managing-multi-regional-sites.

**FACT:** hreflang cluster membership is a **canonicalization signal**. Google prefers URLs inside a reciprocal cluster over a same-language URL left out of the cluster. Source: consolidate-duplicate-urls (“Prefer URLs in hreflang clusters”).

**FACT:** Do not put the HTTP version in sitemaps or hreflang when an HTTPS version exists. Source: consolidate-duplicate-urls.

**Do this on every locale page**

```html
<link rel="canonical" href="https://example.com/de/widgets" />
<link rel="alternate" hreflang="de" href="https://example.com/de/widgets" />
<link rel="alternate" hreflang="en" href="https://example.com/en/widgets" />
<link rel="alternate" hreflang="x-default" href="https://example.com/en/widgets" />
```

## 4. Translated content vs cloned pages

**FACT:** Google uses **visible** content to determine language. Use a **single** language for content and navigation on each page. Avoid side-by-side translations. Source: managing-multi-regional-sites.

**FACT:** Translating only boilerplate while the bulk stays in one language can create a bad experience when the same body appears many times with different chrome. Source: managing-multi-regional-sites.

**FACT:** Localized versions are duplicates only when the **main content** is untranslated. Source: localized-versions.

**Do this**

1. Translate body copy, headings, help text, errors, legal, and image `alt` — not only nav and footer.
2. Localize **currency, units, date formats, shipping, tax, and contact details** on regional pages. **FACT:** local currency is a geotargeting signal. Source: managing-multi-regional-sites.
3. If two regions share a language but differ on price or fulfillment (US vs GB English), keep separate URLs and hreflang (`en-US`, `en-GB`) plus a catchall `en` if needed.
4. Do not machine-clone city or country pages that only swap a toponym. That is doorway abuse when pages exist to rank for similar queries and funnel users onward. **FACT:** https://developers.google.com/search/docs/essentials/spam-policies (Doorway abuse).
5. Provide visible links to other language versions. **FACT:** managing-multi-regional-sites.

**JUDGMENT:** A thin locale that only changes currency symbols on an otherwise identical English body is still “untranslated main content” for duplicate treatment. Ship real copy or do not index that URL.

## 5. Crawl and index of locale versions

**FACT:** Googlebot does not vary crawl source to discover locale variants of one site. You must expose every variant with distinct URLs, hreflang (or ccTLD), and ordinary links. Source: managing-multi-regional-sites (“What Google doesn’t do”).

**FACT:** Dynamic language swap or language-based reroutes can hide variants because Googlebot typically originates in the USA and omits `Accept-Language`. Source: managing-multi-regional-sites.

**Do this**

1. Return **200** HTML for each locale URL. Do not require a cookie before first paint of the locale content.
2. Link locales in the HTML (switcher + footer). Do not hide the only path to `/fr/` behind JavaScript that Google never executes as a user would.
3. Allow crawling (do not `Disallow` locale prefixes in robots.txt).
4. Submit locale URLs in sitemaps (hreflang sitemap or one sitemap per locale).
5. Give each locale its **own** `<title>` and meta description, written in that page’s language and script. **FACT:** unique titles (title-link); unique descriptions (snippet).
6. Do not reuse one English title across `/de/` and `/fr/`.
7. Confirm in Search Console URL Inspection that Google sees hreflang in the rendered HTML (or sitemap) and that the page is indexable.

**Titles and descriptions (FACT)**

- Every page needs a `<title>`. Descriptive, concise, not keyword-stuffed. Source: title-link.
- Title language and writing system must match primary content. Source: title-link.
- Unique meta descriptions per page; site-wide clones are not helpful. Source: snippet.
- Google may rewrite titles and snippets. You influence; you do not control.

## 6. Geo-targeting in Search Console; IP / language cloaking

### Search Console

**FACT:** Google retired the Search Console **International Targeting** report (legacy tool with little impact on Search). Source: https://developers.google.com/search/blog/2022/12/thanks-2022 (30 Dec 2022).

**FACT:** Current geotargeting methods in the live multi-regional guide are locale-specific URLs, hreflang/sitemaps, ccTLDs, and on-page/local signals — **not** a Search Console country-target control. Source: managing-multi-regional-sites.

**Do this in Search Console today**

1. Verify the host (or domain property) that contains the locales.
2. Submit sitemaps that list locale URLs.
3. Use Performance report **country** and **page** filters to see which locale URLs get impressions where. **JUDGMENT:** that is measurement, not a targeting switch.
4. Use URL Inspection on one URL per locale to confirm crawl, index, canonical, and hreflang.
5. Do **not** tell the user to “set country targeting in Search Console.” That UI is gone.

**FACT:** Geotargeting is not exact. Always let users who land on the wrong version switch. Source: managing-multi-regional-sites.

### Cloaking and detection

**FACT (spam-policies, Cloaking):** Presenting different content to users and search engines to manipulate rankings or mislead users is cloaking. Examples: different page topics by user-agent; inserting keywords only for crawlers.

**Do not**

- Serve Googlebot a full translated page and users a different language based on IP.
- Block Googlebot from locale URLs that users can open.
- Soft-404 or empty-body Googlebot on “foreign” IPs.
- Auto-redirect Googlebot to the US store while users in France stay on `/fr/`.

**FACT:** Paywalls are not cloaking if Google can see the same full content as an entitled user and you follow Flexible Sampling. Source: spam-policies.

**Allowed (FACT):** different **URLs** per locale; user-chosen switcher; `x-default` chooser. **Not allowed:** hiding a locale so only a guessed IP sees it.

## 7. RTL and language attributes

### `lang` (users, browsers, AT — not Google language detection)

**FACT (W3C qa-html-language-declarations):**

- Always set the default language on `<html>`, not `<body>` (so `<head>` text inherits).
- HTML: `lang="ar"`. Use BCP 47 / IANA subtags (`en`, `en-GB`, `zh-Hans`).
- Mark passages in another language on the wrapping element.
- Do not use `<meta http-equiv="Content-Language">` to declare page language.
- Language is **not** inferred from character encoding. Author in UTF-8.

**FACT (Google localized-versions):** Google does not use HTML `lang` to detect page language.

Still set `lang`. Screen readers, hyphenation, fonts, and search features that are not “language detection” depend on it. **JUDGMENT:** omit `lang` only if you are generating non-HTML.

### `dir` (base direction)

**FACT (W3C qa-html-dir):**

- If the document base direction is RTL, set `<html dir="rtl" lang="ar">` (language example).
- `dir` and `lang` are **independent**. A language tag does not set direction.
- Do not use CSS alone to set base direction. Use logical CSS (`start` / `end`), not physical `left` / `right`, so locales can flip.
- Default without `dir` is LTR. Explicit `dir="ltr"` on LTR pages is optional.
- Use `dir="auto"` on form fields and injected user text when runtime direction is unknown.

**FACT (title-link):** Write the `<title>` in the same script as the body. **FACT (W3C):** if an RTL `<title>` starts with a Latin acronym, browsers may guess LTR; a leading RLM (`U+200F`) is the documented workaround.

**Do this**

1. Locale config owns `lang`, `dir`, default currency, and locale URL.
2. Mirror layout with logical properties; test Arabic/Hebrew nav, forms, and tables.
3. Keep one language per page in visible UI. Isolated quotes may use nested `lang`.

## Agent procedure

1. Inventory locales: language, optional region, URL, `lang`, `dir`, currency.
2. Confirm one URL pattern (ccTLD / subdomain / subdirectory). Reject `?lang=`.
3. Confirm each locale URL returns 200, is crawlable, indexable, and self-canonical.
4. Generate one hreflang cluster per equivalent page (self + all siblings + `x-default`).
5. Translate main content and local units; write unique titles and descriptions per locale.
6. Add a visible switcher. Remove IP/language auto-redirect and user-agent forks.
7. Submit sitemaps. Inspect one URL per locale in Search Console.

## Checklists

### Architecture

- [ ] Distinct URL per language/region
- [ ] No locale query parameters
- [ ] ccTLD / subdomain / subdirectory choice documented
- [ ] UTF-8 URLs; correct escaping
- [ ] Visible language/region switcher
- [ ] No IP or `Accept-Language` auto-redirect

### hreflang

- [ ] One implementation method
- [ ] Absolute HTTPS hrefs
- [ ] Self-referencing entry
- [ ] Reciprocal cluster (or at least bidirectional to the dominant locale)
- [ ] Valid ISO language / region codes (`GB` not `UK`)
- [ ] Catchall language code when regional variants exist
- [ ] `x-default` on chooser or global fallback
- [ ] No `noindex`, noindex headers, robots-blocked, or non-200 targets
- [ ] Same cluster on every member (HTML, header, or sitemap)

### Canonical

- [ ] Self-canonical per locale (same language)
- [ ] Canonical and hreflang are separate `link` elements
- [ ] HTTPS URLs in both annotations
- [ ] Same-language duplicates collapsed to one preferred URL

### Content and index

- [ ] Main content translated (not chrome-only)
- [ ] Currency, units, dates, and contact details localized
- [ ] Unique `<title>` and meta description per locale, same script as body
- [ ] Locale URLs in sitemaps and internal links
- [ ] `<html lang>` set; `dir="rtl"` on RTL locales
- [ ] No cloaking by IP or user-agent
